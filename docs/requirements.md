# 要件定義書 — LinkedIn海外在宅ワーク特典ページ

## 0. アーキ構成

- 確定アーキ: #6 WEBアプリ（決定論）
- 操作者: ブラウザのエンドユーザー（Instagramリール視聴者）
- AI本体(プロンプトY): なし（ページ自体にAI API呼び出しは発生しない。6種のプロンプトは静的テキストとして埋め込み、読者が自分でClaude/ChatGPT等にコピペする運用）
- MCP: なし
- 自社DB: なし
- フロントUI: あり（このリポジトリそのものがフロントエンド全体）
- 動的変数: なし
- 種別: Web型（静的サイト。バックエンド・DB・ビルド工程なし）
- 配布: マイ専用（発信用GitHubアカウント `mion-ai-mama` 配下の個人リポジトリ）
- ホスティング: GitHub Pages（無料・静的ファイル配信のみ）
- 由来: `mion-ai-mama/instagram-tokuten-template`（テンプレートリポジトリ）を「Use this template」で複製して作成。元テンプレートは編集していない。

補足: 前作「AIで人気動画を分析する方法」ガイドと同一アーキ・同一技術スタックを踏襲。
テンプレートの再利用性を実証する2件目のインスタンス。

## 1. プロジェクト概要

- 成果目標: Instagramリールの視聴者に配布する特典資料として、「LinkedInを使って海外の
  在宅ワークを探し、AIを活用して求人内容の確認・応募準備・実作業を効率化する方法」を
  1ページ完結型のGitHub Pagesサイトとして提供する。
- ターゲット読者: AI初心者〜初級者の30〜50代女性。在宅ワークに関心があるが、海外案件・
  英語・LinkedInのいずれにも苦手意識がある層。
- 制作方針: 「noteの読みやすさ × Webページならではの便利さ」。派手なLP演出（グラデーション・
  過剰アニメーション・黒背景・複雑なメニュー・過度なCTA・カード多用）は行わず、文章と
  画像とコピー機能が縦に並ぶ、教材を読む感覚のページにする。

### 成功指標（定量）

- フッターまでのスクロール到達率（読了率）
- 6種のプロンプトの合計コピー率（コピーボタン押下 ÷ 閲覧数）
- STEP3の検索キーワード（9語）のコピー率
- STEP9チェックリストの平均チェック数（10項目中）
- 2本目以降の特典ページ制作時間（`content.js`編集のみで完結する時間・テンプレ効果の実証）

### 成功指標（定性）

- 「英語もLinkedInも初めてだけど私にもできそう」と思える心理的ハードルの低さ
- note感覚で縦スクロールするだけで理解できる没入感（サイトっぽさを感じさせない）
- 40代女性が見ても幼稚に感じないデザイン品質
- スマホでの読みやすさ・タップしやすさ（コピー操作のストレスのなさ）
- 「求人を探す→AIに確認させる→応募準備する」という一連の流れが迷わず追える構成

## 2. 想定読者（ペルソナ）

- 30〜50代女性、AI初心者〜初級者
- 在宅でできる仕事を探している。海外案件に興味はあるが英語に苦手意識がある
- LinkedInを使ったことがない。ClaudeやChatGPTは少し触ったことがある
- 家族との時間を大切にしながら収入の選択肢を増やしたい

デザイン・文章とも「私にもできそう」「この通りにやればいい」と思える平易さを最優先する。
かわいすぎるデザインは避け、40代女性が見ても幼く感じない清潔感を重視する。

## 3. デザイン方針

- 基本カラー: 白／オフホワイト／淡いベージュ／ごく薄いグレー
- アクセントカラー: くすみブルー／淡いネイビー／少量のゴールド系ベージュ（色数を増やしすぎない）
- フォント: 読みやすい日本語ゴシック体。本文16〜18px（スマホで小さくなりすぎない）。見出しは
  大きくしすぎず読みやすさ重視
- 余白: noteのようにしっかり確保。1画面あたりの情報量を増やしすぎない
- 禁止事項: 派手なグラデーション、過剰なアニメーション、高級感の出しすぎ、黒背景、
  ギラギラしたAI感、複雑なメニュー、サイドバー、不要なポップアップ、過度なCTA、
  カードへの過度な分割

## 4. レスポンシブ対応（最重要）

InstagramのDMからスマートフォンで閲覧するユーザーが中心。以下を必ず満たす。

- iPhoneで横スクロールが発生しない
- 本文が小さくならない（最小16px維持）
- ボタン・コピーボタンがタップしやすいサイズ
- プロンプト・長い英語文章が画面からはみ出さず折り返される
- 画像が適切に縮小される
- PCでも崩れない

## 6. 必須機能（実装仕様）

| # | 機能 | 仕様 |
|---|---|---|
| 1 | プロンプトコピー | 各PROMPT（6個）に「コピーする」ボタン。押下でクリップボードへコピーし、「コピーしました ✓」を1〜2秒表示 |
| 2 | 検索キーワードコピー | STEP3の9語それぞれに個別コピーボタン。コピー後「コピーしました」を短時間表示 |
| 3 | チェックリスト | STEP9の10項目をタップでチェックON/OFF。状態は`localStorage`に保存し、再読み込みでも保持。任意入力（未チェックのまま次に進んでよい） |
| 4 | 目次スクロール | 「このガイドの流れ」からSTEP1〜9へスムーズスクロール。PC向けメニューバーは作らない |
| 5 | 画像枠 | 各STEPにスクリーンショット枠を設置。画像未設定時は「ここに◯◯の画像を追加」という管理者向けプレースホルダーを表示し、レイアウトは崩れない。画像は`/assets/images/`配下に置けば差し替え可能 |

## 7. データ設計概要

DBは使用しない。全コンテンツは`js/content.js`の`CONTENT`オブジェクトで一元管理し、
`js/script.js`がDOMへ反映する。チェックリストのON/OFF状態のみブラウザの`localStorage`に
保存する（サーバー送信なし）。`index.html`にはJavaScript無効時のフォールバック表示を
直接記述する。

## 8. セキュリティ要件

- 個人情報の入力フォームなし、認証機能なし、決済機能なし → 該当するセキュリティ対策は最小限
- HTTPS: GitHub Pagesは標準でHTTPS配信
- 外部リンク（LinkedIn検索・LINE誘導ボタン等）は`rel="noopener"`を付与
- `localStorage`にはチェックリストのON/OFF（真偽値10個）のみ保存し、個人情報は一切保存しない
- 入力フォームが存在しないため、CSRF・入力サニタイズ等の対策は対象外

## 9. 技術スタック

- HTML5 / CSS3 / Vanilla JavaScript（ES2017相当。フレームワーク・ビルド工程なし）
- フォント: システムフォント（追加のWebフォント読み込みなし）
- ホスティング: GitHub Pages（`main`ブランチ / root）
- ビルドツール・パッケージマネージャ: 使用しない
- データベース・サーバーサイド処理: 使用しない
