# 要件定義書 — Instagramリール特典ページ（GitHub Pages型テンプレート）

## 0. アーキ構成

- 確定アーキ: #6 WEBアプリ（決定論）
- 操作者: ブラウザのエンドユーザー（Instagramリール視聴者）
- AI本体(プロンプトY): なし（ページはすべて静的。コンテンツはChatGPTとの壁打ちで事前に決定し、静的テキストとして埋め込む）
- MCP: なし
- 自社DB: なし
- フロントUI: あり（このリポジトリそのものがフロントエンド全体）
- 動的変数: なし
- 種別: Web型（静的サイト。バックエンド・DB・ビルド工程なし）
- 配布: マイ専用（発信用GitHubアカウント mion-ai-mama 配下の個人リポジトリ。本名アカウントとは分離。BlueLampテナント配布ではない）
- ホスティング: GitHub Pages（無料・静的ファイル配信のみ）

補足: 一般的な6アーキ判定ではWebアプリ=React+FastAPI+DBを想定するが、本件はユーザーの
明示要件により「複雑なビルド環境・DB・サーバーサイド処理を使わない」ことが必須条件。
そのためHTML/CSS/JSのみの完全な静的サイトとして構築する（技術スタックは§7参照）。

## 1. プロジェクト概要

- 成果目標: Instagramリールの視聴者に配布する特典資料を、これまでのnoteに代わり
  GitHub Pages上の1ページ完結型LP（ランディングページ）として提供する。
- 今回作る特典の内容: 「AIで人気動画を分析する方法｜コピペで使える3STEPガイド」
  （ChatGPTに人気動画のスクショを見せて分析させる手法を、3STEPで解説）
- 重要な制約: 今回の特典ページは「使い捨ての1ページ」ではなく、**今後の特典制作でも
  複製して使えるテンプレートリポジトリ**として構築する。GitHubの「Use this template」
  機能で複製し、`js/content.js` の中身を差し替えるだけで新しい特典ページを作れる状態にする。

### 成功指標（定量）

- 特典ページ → LINE登録ボタンのクリック率
- リールのプロフィールリンク経由の特典ページ到達率
- ページ平均滞在時間（最後まで読了されるか）
- 1本あたりの制作時間（note比で短縮。テンプレ化により2回目以降は`content.js`編集のみ）

### 成功指標（定性）

- スクロールごとに「自分にもできそう」と感じさせる没入感
- スマホでサクサク読める、情報過多に感じさせない余白・構成
- noteより視覚的にリッチで専門性・信頼感を感じさせるデザイン
- テーマが変わっても骨組みは共通で使い回せるテンプレート性
- コードに詳しくない人でも `content.js` 中心の編集で運用できる

## 2. 想定読者（ペルソナ）

- 40代・50代、AI初心者、ChatGPTを使い始めたばかり
- 専門用語が苦手、スマートフォンで閲覧
- 自分で発信の企画を考えることに苦手意識がある

デザイン・文章とも「私にもできそう」「この通りにやればいい」と思える平易さを最優先する。

## 3. ページ構成（1ページ構成・全13セクション＋実例動画セクション）

| # | セクション | 内容概要 |
|---|---|---|
| 1 | ファーストビュー | ラベル／タイトル／サブタイトル／説明文／CTAボタン(STEP1へスムーズスクロール) |
| 2 | 実例動画 | 実際に作成した動画の埋め込み（mp4直置き／YouTube限定公開の切替式、実際の縦横比に自動対応、showVideoでON/OFF可） |
| 3 | メインプロンプト | コピペ用プロンプト＋コピーボタン（実例動画の直後に配置し、早い段階で価値を提示） |
| 4 | STEP1 | 気になる人気動画を見つける（短縮版：リード文1行＋おすすめ動画の箇条書き＋まとめ1行） |
| 5 | STEP2 | 動画のスクショを撮る（短縮版：リード文1行＋撮るシーン例の箇条書き＋補足ボックス） |

| 7 | 結果をよくするコツ | 3カード |

| 9 | 注意点 | 2〜3行に短縮 |
| 10 | 最後の案内(CTA) | 『AIマネタイズの教科書』LINE登録導線（バナー画像クリック） |

> 2026-07-27改訂: Instagramからの初心者が3分以内に読了できるよう、「はじめに」「この方法でできること」「まとめ」の3セクションを削除し、メインプロンプトを実例動画の直後に移動。STEP1・STEP2・注意点を大幅短縮した。

## 4. データ設計概要

DBは使用しない。全コンテンツは `js/content.js` の `CONTENT` オブジェクト（JavaScriptの
定数）で一元管理し、`js/script.js` がページ読み込み時にDOMへ反映する。`index.html` には
初期値として同内容を直接記述し、JavaScript無効時のフォールバック表示を担保する。

## 5. セキュリティ要件

- 個人情報の入力フォームなし、認証機能なし、決済機能なし → 該当するセキュリティ対策は最小限
- HTTPS: GitHub Pagesは標準でHTTPS配信
- 外部リンク（LINE誘導ボタン等）は `rel="noopener"` を付与
- 入力フォームが存在しないため、CSRF・入力サニタイズ等の対策は対象外

## 6. 技術スタック

- HTML5 / CSS3 / Vanilla JavaScript（ES2017相当。フレームワーク・ビルド工程なし）
- フォント: システムフォント（追加のWebフォント読み込みなし）
- ホスティング: GitHub Pages（`main` ブランチ / root）
- ビルドツール・パッケージマネージャ: 使用しない
- データベース・サーバーサイド処理: 使用しない

## 7. 外部サービス一覧

| サービス | 用途 | 費用 |
|---|---|---|
| GitHub Pages | 静的サイトホスティング | 無料 |
| LINE公式アカウント | 特典受け取り後の登録導線（既存の導線をそのまま利用） | 既存のため対象外 |
| YouTube（限定公開・任意） | 動画埋め込み先の選択肢（mp4直置きの代替） | 無料 |

## 8. AI設計

該当なし（AI本体Yなし）。特典コンテンツ自体は、著者がChatGPTとの壁打ちで事前に作成し、
静的テキストとして埋め込む運用。ページ自体にAIのランタイム処理は含まれない。

## 9. テンプレート化要件

- GitHubの「テンプレートリポジトリ」設定を有効化し、「Use this template」で複製可能にする
- 複製後に変更が必要な箇所は `js/content.js` に集約（タイトル・導入文・STEP内容・
  プロンプト・追加質問・CTA文言・CTAリンク・フッター表記・動画設定・SEO/OGP情報）
- README.md に、複製方法・編集方法・公開方法を非エンジニア向けに日本語で記載
